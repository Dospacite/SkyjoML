# Results

Generated by `benchmarks/make_report.py` from `artifacts/reports/*.json`.

Unit conventions: **win credit** is the candidate's expected share of the win (1/k for a k-way tie).
**credit × n** rescales it by the table size so that 1.0 is parity at any player count (e.g. 2.0 at 4 players = 50% win credit where a random seat gets 25%).
Every cell uses paired deals: each deal seed is played n times with the candidate rotated through every seat;
95% intervals are percentile bootstraps over deal blocks (seed + all rotations).

## Engine integrity and speed

- Randomized gate: 100,000 complete matches (50,418,027 decisions; policy mix {'random': 44910, 'stall': 10013, 'heuristic': 45077}), errors {'census': 0, 'negative_public_pool': 0, 'no_legal_action': 0, 'illegal_step': 0, 'score_inconsistency': 0} → **PASS**. 1062 matches hit the watchdog.
- Breakdown rerun (10,000 matches, seed 7, errors 0): watchdog stops by policy {'random': 0, 'stall': 0, 'heuristic': 109} out of {'random': 4508, 'stall': 925, 'heuristic': 4567}. All come from all-heuristic tables, most likely because the `finish` heuristic avoids revealing its last card when it expects to be doubled (not separately diagnosed), so a table of them can cycle indefinitely. Truncated matches are never scored as results; training saw 4 in ~107k matches.
- Batch engine, single thread, uniform-random legal actions incl. observation/mask generation: 2p 62,816/s, 3p 40,293/s, 4p 57,662/s, 5p 72,009/s, 6p 78,292/s, 7p 76,675/s, 8p 70,162/s transitions.
- Heuristic ladder (credit × n, 200 dev deals × rotations): 2p greedy vs random 2.0; 2p column vs random 2.0; 2p column vs greedy 1.212; 2p finish vs random 2.0; 2p finish vs greedy 1.562; 2p finish vs column 1.252; 4p greedy vs random 4.0; 4p column vs random 3.99; 4p column vs greedy 1.478; 4p finish vs random 4.0; 4p finish vs greedy 1.789; 4p finish vs column 1.365.
